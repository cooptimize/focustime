# Coopilot

Local, visual week-planning and focus app for Tanner on Omarchy. A week grid of half-day focus blocks with meetings and personal events layered on, risk flags, and (later) a conversation panel that calls the same actions as the UI.

Read before changing code: this file, `docs/spec.md` (current slice), `docs/decisions.md`.

## Principles

- **#1 DevOps first.** We plan, track and show work in DevOps; if it isn't in DevOps, it isn't planned yet. Coopilot makes the healthy path the easy path, without policing, and re-planning never feels like failure.
- **Nothing machine-specific in core modules** (`week/`, `plan/`, `actions/`, `sources/`). OS integrations (keyring, Edge/Chromium launch, notify-send, playerctl, Hyprland) stay behind thin host adapters, so a hosted version stays possible later.

## Hard rules

- All external systems are read-only, except Outlook events Coopilot created (step 12), help invites it sends to Cooptimize addresses and the time and show-as of my own events with no other attendees (step 13) and my response (accept, tentative, decline, with an optional note and proposed time) to meetings someone else invited me to (step 16), written only through the write framework (`actions/timebox-actions.ts`: preview, confirm, read back, audit log, undo; marker required on Coopilot's events, never added to mine). Meetings with other attendees are never edited: an RSVP only calls Graph's accept, tentativelyAccept or decline, never PATCH, DELETE or cancel. DevOps (step 14): only the named writes in `actions/devops-write-actions.ts` (state, comment, create from a draft, target date on my feature or epic, and their undos), each with preview, `test /rev`, read back, audit log and undo, with my personal write PAT for that client only, never deletes. No writes to Dataverse, Google, Teams. The plan (picks, drafts, done ticks) lives only in the local plan store.
- Teammates' free/busy (Graph getSchedule): keep only free/busy and working hours; never store, log or display subjects, locations or other details of their events. Teammates' PTO shows only as "away", never the title.
- Secrets live only in the OS keyring (service `coopilot`). Access tokens in memory only. Never log, cache, export or print tokens, secrets, Authorization headers or raw HTTP bodies.
- DevOps PATs: the company read PAT is read from Dataverse only at DevOps fetch time (`devopsTargets`), and never on the write path (`{withPat:false}`). My write PATs (step 14) live only in the keyring (`devops-write-pat:<client>`), entered in Settings, checked against my DevOps identity before saving. Both are wrapped in `Pat` (prints as `[PAT]`), used only for the Authorization header to `https://dev.azure.com/<org>/`. Never logged, cached, returned to the UI, exported, or asked for in chat.
- Core views work with no AI provider. AI never executes anything; it only suggests via allowlisted actions.
- Localhost server (if any): bind 127.0.0.1, check Host and Origin, per-launch token.
- Do not touch Hyprland, Omarchy, browser profiles, Remmina or existing keyring entries.
- Client data stays scoped to its client in views and drafts.

## Working style

- Small end-to-end steps. Define behavior first; failing test where it matters (normalization, risk rules, secret handling, failure isolation, persistence); implement; refactor.
- No tests for trivial styling or that mirror implementation.
- Type-check before calling a step done. Inspect the real UI (screenshot) for UI changes.
- Verify current official docs before version-specific integration code.
- Record decisions in `docs/decisions.md` and open questions in `docs/open-questions.md` as they come up.
- Plain language in UI copy. No em dashes.
- Commit and push to `origin` (the private GitHub repo `coopilot`) after each completed step.
- Never commit secrets (PATs, client secrets, tokens, Authorization headers, keyring values) or real personal or client data (real names, emails, client DevOps orgs or projects, work item titles, calendar subjects, screenshots of real data). Tests and fixtures use fakes (`@example` addresses, `contoso`/`fabrikam` orgs); screenshots in the repo come from demo mode only. Local stores, backups, footage and config stay out of git (`.gitignore`).
