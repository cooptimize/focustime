## RB-7: Code on a branch you choose (Nov 19)

Unnumbered until merge.

| # | Status | Decision |
|---|---|---|
| - | Done | Why: work often lives on another branch than the repo's default ("the work is on dev, not main"), and Code showed only the default. A person can now choose the branch beside the repo's name, and an admin can set the branch a client's repos open on. Everything else about Code holds: read only, one client at a time, nothing kept, no AI. |
| - | Done | The one new read: a repo's branch names, `GET https://dev.azure.com/<org>/<project>/_apis/git/repositories/{repo}/refs?filter=heads/&$top=1000&api-version=7.1` ([Refs - List](https://learn.microsoft.com/en-us/rest/api/azure/devops/git/refs/list?view=azure-devops-rest-7.1)), in `ALLOWED` as `branches` with both values fixed (`FIXED`) and required, so it can reach branch heads only: never tags or another kind of ref, never another project, never a write. Only each ref's `name` is read (its creator, a person, never is). The same token, limiter and 5-minute memory as every Code read. |
| - | Done | One page of 1000 branch names, no continuation token: the Refs page names `$top` (at most 1000) and `continuationToken` but not where the token comes back. A repo with more says "Showing the first 1,000 branches." in the picker. |
| - | Done | Which branch a read is on (`plan/code-branch.ts`, `pickBranch`): a branch chosen in the address while the repo has it; else the client's opening branch when the repo has a branch of that name; else the repo's default. The branch list is read only when a branch other than the default is asked for; with none set and none chosen nothing more is read than before RB-7. |
| - | Done | The opening branch is a client Rule, `code_branch` ("Code opens on", Admin › Clients › <client> › Code, beside who can read its code), stored like every client Rule (an `org_settings` row), so no migration. It is offered from the names the client's repos really have (`admin.code_branches`, read through Code's own checks as the admin), never typed; Each repo's default clears it. The tab lists each repo with the branch it will open on, and "(it has no dev)" where it opens on its default. A value that isn't a branch's name is refused (`isBranchName`, git's own rules). |
| - | Done | The picker sits beside the repo's name (Files) and beside "In <repo>, <folder>" (By kind). It is Code's client picker (its button, list and option styles) under its own class names. The list is read when it first opens: the opening branch first and marked "opens here", the default next when it differs and marked "default", then the rest A to Z; over 20, a box to find one by typing; a long name is cut in the middle (36 characters) with the whole name on hover. |
| - | Done | The address carries a choice as `#/code/<client>/<repo id>@<branch, encoded whole>/<path>` (a "/" in the name is %2F), only while it differs from the usual branch; an address made before RB-7 opens as before. It is never kept in the browser's storage or on the server: the last place kept is still only that Code was the tab, and a fresh open starts on the opening branch. Copy link carries the branch; Copy DevOps link gives the file on the branch on screen (`version=GB<branch>`). |
| - | Done | The header's line, when the branch on screen isn't the usual one: "On feature/returns, not the usual dev" with "Back to dev". A branch in an address, or one deleted while a person reads, that isn't there any more falls back to the opening branch with "feature/old isn't there any more, so this is dev." (a not-found on a chosen branch reads the branch list afresh once to tell). Choosing a branch where the open file isn't goes to the nearest folder that is: "<path> isn't on main, so this is <folder>." |
| - | Done | What follows the branch: the tree, a file, Find, By kind (and its SQL tree, reports and models), and Search names, for the repo on screen; every other repo of the client is read on its opening branch. A result opens on the branch its names were read on. |
| - | Done | Search inside files asks DevOps as before and keeps a hit only when DevOps says it is on that repo's branch (`versions[].branchName`): the branch on screen for the repo on screen, the opening branch for the rest. When DevOps found the words on the repo's default and never on that branch, it doesn't search that branch ("By default, code search in files applies only to the default branch. You can add up to five more branches to search."): that repo says "DevOps doesn't search this branch. These are from main." and shows the default's hits. FocusTime never changes a client's searchable branches. |
| - | Done | Opening branch only, no branch from a person: Where is it? (`code.kinds` with `from`, and `code.inner`) refuses a branch or a repo; a search with no repo on screen reads every repo on its opening branch. |

Reading the branch list writes no row: it is branch names, not code. |
