## RB-1: Code, every client's repos, read only (Nov 12)

Unnumbered until merge.

| # | Status | Decision |
|---|---|---|
| - | Done | Why: Cooptimizers borrow working code from one client to start the same job at another, and today only someone with a login at both can. Tanner (Nov 12): "if we are not on another client but want to access the repo for reference purposes.. this solves for that. Who sees it... everyone." Code gives every Cooptimizer one place to open any client's repos, walk the tree and read a file, read only. |
| - | Done | The exception: every Cooptimizer may read every client's code, a deliberate exception by the product owner to "one client's data never shows outside that client". It covers code read through Code and nothing else; work items, chats, promises, transcripts and reports keep every rule. Written into CLAUDE.md (Client code (RB-1), the DevOps PATs rule and the client boundary's Unchanged line) and `docs/technical/security.md`. |
| - | Done | Who: a Cooptimizer by the existing people rule (`notCooptimizer` in `plan/person-match.ts`: guests, people outside the Cooptimize domains and automation accounts are refused on every read). The team for Its team only is the client status report's check (`reportTeam().onClient`, `actions/team-actions.ts`), not a new rule. Clients come from `clientAccounts()`, so a hidden client isn't listed and can't be read by its key. |
| - | Done | The per-client Rule "Who can read this client's code" (`code_access`: `company`, the built-in default, or `team`) in Admin › Clients, recorded in `admin_audit` like any Rule. A team-only client stays in everyone else's list, greyed, with "Only <client>'s team can open this" and no repo names. |
| - | Done | The reader (`sources/devops/git.ts`): an allow list like the Azure client's, with only GETs to `https://dev.azure.com/<org>/<project>/_apis/git/`: the project's repos, one folder level, every file name (Find), a file's metadata and its bytes pinned to the commit. Anything else throws before a request. The org and project come from the client's Dataverse account; the browser sends a client key, a repo id that must be in that client's list, and a path, which travels only as a query value and can't leave the repo. Checked against the Azure DevOps REST 7.1 docs (Repositories - List, Items - List, Items - Get) in step 0. |
| - | Done | The default branch only. A repo with no default branch is "empty", a disabled one says so; neither gets a request for items. |
| - | Done | Text files up to 1 MB are shown. A larger `Content-Length` isn't read at all; a stream stops at 1 MB and 1 byte. Binary files (a zero byte in the first 8,000 bytes, git's own test, or bytes that aren't UTF-8; DevOps's `isBinary` alone isn't trusted), images (except SVG, which is text) and larger files say why and their size, with no text. A Git LFS pointer is shown as it is (`resolveLfs` is never sent). |
| - | Done | The token: the company read PAT from Dataverse at each read (`accountTargets`) and dropped, keeping less than the poller's 10 minute memo; in `Pat`, used only for the Authorization header. A token without Code (read) (401, 403, 203, a redirect or a sign-in page; Microsoft doesn't document which) says "FocusTime can't read <client>'s code yet. The company DevOps token for <client> needs Code (read)." The product owner adds the scope by hand. |
| - | Done | Memory, not storage: repo lists, folder lists, file names and file text stay in the server's memory at most 5 minutes (500 entries, 40 million characters), keyed by client, repo, commit and path, reached only after the access check. Nothing of the code goes to the database, disk, logs, Application Insights, error messages, Export or the browser's storage; the stored last place leaves out a Code address. Every `/api` response is no-store and the service worker never caches `/api`. |
| - | Done | The view log `code_views` (an app table; migration `20261113T0022_code_views`): when, who (id and name), client, repo id and name, path, and what (repo opened, file opened, Find used); never content. Opening a repo's top folder counts as opening the repo; other folders aren't logged. A file's row is written before its text is returned; if it can't be written, the person sees "The file wasn't opened because FocusTime couldn't record that you opened it. Try again in a moment." and no text. Kept 12 months by the daily retention purge. Admin › Audit › Code views: newest 200, filters for client and person, counts per client for the last 30 days, admins only. |
| - | Done | The panel (`ui/code/Code.tsx`, loaded only when opened): `#/code`, `#/code/<client>`, `#/code/<client>/<repo id>/<path>`, from ⋯ (beside Technical docs) and the command menu ("Code", "Code: <client>" for each client the person can open). On ST-1's panel shell like the Technical docs. The client's name and color and "Read only" in the header the whole time. Left: the client picker (mine first, then the rest), the repo select when there is more than one (a lone repo opens on its own), Find a file, the tree; right: breadcrumbs, size, language, line count, Copy, Copy path, Copy DevOps link, Copy link, Wrap. The log line once at the foot of the left side. |
| - | Done | The tree is an ARIA tree (Up, Down, Home, End, Right opens or moves in, Left closes or moves to the parent, Enter); a folder opens in place with one request; Backlog's chevron. Find loads the names on first use (up to 20,000, and says when the list was cut), matches every word typed, Up, Down and Enter; no key of its own (none was free that wouldn't fight typing in the tree). Esc closes the client list first, then the panel. |
| - | Done | The coloring library is Prism 1.30.0 (MIT): out of the box it has SQL, JSON, YAML, XML, PowerShell, Markdown, Python, DAX and Power Query (M); its core is about 2 KB gzipped and each grammar 0.3 to 0.5 KB; only its core and the nine grammars are loaded (`prismjs/components/prism-core`; the package's main file also carries the file-highlight plugin, which can request a file, so it is never imported), in manual mode, with no network call; `Prism.tokenize` returns a token tree, never HTML, so FocusTime draws each piece as a text node, and the core's HTML highlighter is never called (`ui/code/viewer.test.ts` checks the sources). highlight.js was the other candidate: its DAX and M are third-party and its API returns HTML. |
| - | Done | TMDL has no Prism grammar, so `ui/code/tmdl.ts` is a small one: object keywords, names, properties, annotations and descriptions, and the expression after "=" handed to DAX or M by what it belongs to (a measure, calculated column, calculation item or table permission is DAX; an M partition's source and a shared expression are M). A multi-line expression after an object's "=" is the lines deeper than its properties, so the properties after a measure stay properties. |
| - | Done | A file's language comes from one table (`ui/code/languages.ts`): by name, then extension (SQL, SQL projects as XML, Fabric and Power BI definitions and `.platform` files as JSON, TMDL, DAX, M, Python and notebooks stored as source, YAML, XML, PowerShell, Markdown), then its first lines; anything else is plain text. Over 5,000 lines or 300 KB it is shown plain with "Coloring is off for large files." Colors are the theme's `--code-*` tokens in all four theme blocks. |
| - | Done | Format: only for JSON squashed onto one or a few very long lines; it changes whitespace only and leaves broken JSON alone with a plain reason. Copy copies the file exactly unless Format is on, and the button says which ("Copy" or "Copy formatted"). |
| - | Done | The phone: the client list, then the client's repo, Find and tree as one page, then the file as its own page with Back to the repo. No sideways page scroll; the file scrolls in its own box or wraps. |
| - | Done | Admin › Clients › <client>: the Rule and "Can FocusTime read it?" with "Code: readable · 3 repos", "Can't read yet: the token needs Code (read)" or "No DevOps set up", checked when the card opens and on Check, never on a schedule. |
| - | Done | Demo (`sources/demo/code.ts`, wired in `server/demo.ts` only): invented repos for each demo client (a semantic model in TMDL, a report with a squashed `report.json`, a Fabric pipeline and notebook, a Data Factory pipeline, SQL, a SQL project, YAML, PowerShell, a README, an HTML page with a script, an SVG, a PNG, a binary `.pbix`, a 3.4 MB CSV, a Git LFS pointer, an empty repo), a new invented customer Fabrikam set to its team only, and Harbor's token without Code (read). |
