## NT-1: Notices and reminders know a day off (Nov 17)

Unnumbered until merge.

| # | Status | Decision |
|---|---|---|
| - | Done | The cause: a hosted person's Dataverse user is kept with their sign-in, not in their settings, and a person's background (`server/ticks.ts`) read the raw settings. With no Dataverse user there was no PTO read, so every PTO day looked like a working day: "Quiet on PTO days" never quieted anything, and Plan today, Plan the week, Check-in, Close out, the look-ahead, the direction review, the status nudge, the Teams rhythm and the VM's morning prompt all went out. Only the VM start (VM-3) had the identity. The failing test came first (`server/ticks-nt1.test.ts`). |
| - | Done | STEP 0.4, the background's identity-dependent reads: the gate's PTO, the day reminders', the Ahead rituals', the status nudge's, the Teams rhythm's (through the gate), the VM's morning prompt and urgent requests' followed clients had no identity; the VM start, story taken and notes, Team, calls to review and Monday's status (through `dispatch`) had it; calendar refresh, expiring secrets, Teams status and the jobs' own settings reads don't depend on it. All of the first group are fixed. |
| - | Done | The background reads a person's settings one way: `bg = d.policy.production ? withSignedIn(liveCtx) : liveCtx`, the context a request has, for every part. Outside production the raw settings, so nothing new is read there. `server/ticks-identity.test.ts` fails on any raw use of the person's context other than its plain ports and `dispatch` (which signs itself). |
| - | Done | A day off for notices is whole-day PTO or a company holiday, from the VM start's two Dataverse reads. One reader per person (`server/days-off.ts`) answers for the gate, the reminders, the Teams rhythm, the VM's morning prompt, the chip's Next line read in the background and the VM start: one read of each for a 14 day window from today, at most every 30 minutes, kept per day and Dataverse user. |
| - | Done | What a day off does is unchanged: the reminders skip it whatever the setting; the gate quiets the rest when the setting is on; the timer and meeting warnings still come. The VM morning prompt's own rule stays PTO only (a holiday reaches it through the gate). |
| - | Done | PTO that can't be read fresh: a read from the last 24 hours (`PTO_STALE_HOURS`) that covers the day, this reader's or the VM start's stored one. Otherwise unknown: the gate sends, while the day's reminders, the Ahead rituals and the status nudge wait and are asked again on a later pass. No Dataverse user found for the sign-in isn't a failed read: not PTO, as before. Holidays that can't be read: a working day. |
| - | Done | Failed reads are logged once a day per reason, `dataverse day_off pto_unread`, `pto_unread_earlier` or `holidays_unread`, with no name, id, date or holiday name. |
| - | Done | The VM start is unchanged: when the kept read failed, the start and the chip read again (as on every pass before), and a shared read that hasn't answered in 60 s (`DAY_OFF_READ_LIMIT_MS`) is unread, so one stuck read can't hold the start. VM-2's tests pass unchanged. One VM-3 test (a gate whose PTO read hangs) moves its second pass from 9:02 to 9:26, past the shared read's 30 minutes, so the gate's read is a fresh one: the test's point is kept. |
| - | Done | Outside production nothing is read and no day is off (`ticks-nt1.test.ts`); before, a developer whose settings held a Dataverse user got PTO quiet on a test site with the opt-in. |
| - | Done | Words: "Quiet on days off" with the hint "PTO and company holidays from Dataverse." (`DAYS_OFF_WORDS`, `plan/notify.ts`), the field still "Days off"; Settings search still finds "Quiet on PTO days". The stored setting (`[notify] quiet_pto`), its default and values are unchanged. The Guide, wording.md and `docs/technical/operations.md` say what a day off is. |
| - | Done | Nothing new is told: no notice, setting, migration or dependency. |
