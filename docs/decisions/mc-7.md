## MC-7: Paste a transcript or your notes into a call (Nov 19)

Unnumbered until merge.

| # | Status | Decision |
|---|---|---|
| - | Done | 1. **Paste** is one more transcript choice, beside From Teams, Pocket recording, A file and Later, wherever the choices show: Add a call (its button stays "Add and review"), and the page of a call with no transcript ("Use this"). A call that has a transcript gets "Paste a transcript or notes" in its menu, right under Upload a transcript; its box opens above the proposals. |
| - | Done | 2. One box (the shared `TextBox`, 12 lines tall, growing to 24 then scrolling), labelled "Paste a transcript or your notes". A textarea takes plain text only; nothing in it is run or drawn as markup (React text everywhere it shows). |
| - | Done | 3. As soon as there is text, one line under the box says what FocusTime took it for and how much ("A transcript: 142 lines, 4 speakers", "Notes: 23 lines"), with one quiet link to read it the other way ("Read it as notes", "Read it as a transcript"). The press sends the reading the line shows. |
| - | Done | 4. The text is held in the page's memory only (`usePaste`, `ui/meetings/PasteBox.tsx`): never in the browser's storage (`autoComplete="off"`), so a reload loses it. While text is in the box the page holds the browser's unload ("Leave site?"), and Cancel or Esc in Add a call, or Cancel on the replace box, asks "Leave without using what you pasted? FocusTime doesn't keep it." |
| - | Done | 5. Limits: what a file may be (5 MB, `MAX_TRANSCRIPT_BYTES`, now shared with the file intake) and at most `MAX_LINES` (4000) lines once read; over either is refused with "That is longer than FocusTime can read for one call. Paste the part that matters." (said under the box before any press, and by the server). Fewer than 3 words: "Paste at least a few words." Nothing is saved for either. A file over 4000 lines is still cut, as before; only a paste is refused. |
| - | Done | 6. A pasted transcript (`readPaste`, `plan/transcript.ts`, pure) reads: a pasted .vtt (the same cues as the file, so the same lines); "Name: words"; a name and a time on one line with the words under it; a name alone with its time on the next line; a time, then a name, then words ("00:01:02 Name: words", "[0:03] Name: words"); a time alone (its next speaker's); an .srt cue number (skipped); numbered or lettered voices ("Speaker 1", "Speaker B", "Participant 2"). A line that fits no shape joins the line before it; one before any speaker is "Unknown". Times are times into the call; a clock time ("10:03 AM") is no time into it, so it is left out. Consecutive lines of one speaker merge, as a file's do. |
| - | Done | 7. A name is one to five words, each capitalised (or van, de, bin and the like), at most 60 characters, or a numbered voice. Words notes put before a colon ("Decision:", "Next steps:", "Action items:", "Owner:", ...) are never a speaker. |
| - | Done | 8. Which reading: a transcript when at least two lines carry a speaker, they are at least as many as the lines that don't, and at least half of them are sure (their speaker comes back, or the line has a time); a pasted .vtt always. Otherwise notes. So "Budget: 40k / Timeline: two weeks" is notes, and "Ana: hi / Ben: hi" is notes until switched. |
| - | Done | 9. Notes: each line the reviewer wrote is one line, blank lines and bullet marks (-, *, •, 1., a), [ ], >) dropped; no speaker (stored as ""), no time; a line over 1200 characters is split at a sentence end, as a transcript's. |
| - | Done | 10. Two new transcript kinds, `pasted` and `pasted_notes` (`TRANSCRIPT_KINDS`). The column `transcript_kind` is checked by no constraint, so no migration. What each changes: the call's line says "Pasted transcript" or "Pasted notes" (where Pocket said "Pocket"); a call's source line "Transcript pasted by a reviewer" or "Notes pasted by a reviewer"; the review says `pasted`. Notes: the Transcript tab and view are "Your notes", with no speaker column and no time, its filter's hint "Words"; a proposal's quote shows the note alone, labelled "Open your notes at this line", and opens that line. A pasted transcript shows its names and times as a file's. |
| - | Done | 11. A pasted transcript's names are names, as an uploaded file's (`speakersNamed`); one with any numbered voice is treated as unnamed, as Pocket's (the AI gets PK-1's sentence and promises' owners come only from the words). Notes are never named speakers. |
| - | Done | 12. The AI is told, for notes only, in one added sentence (`NOTES_INSTRUCTION`): "This text is notes written by a person who was on the call, not what was said word for word: never credit a line to a speaker or treat a note as a quote, and for a commitment's who give only a name the note itself writes, or I where the writer says I or I'll." Notes have no speakers, so the input has no Speakers list and each line is "L4 words". Nothing else in what it is given changes; a pasted transcript is given exactly what a file of the same words is. |
| - | Done | 13. A promise from notes is someone's only when the note says whose: "I" where the cited note says I is whoever pasted the notes (the transcript's `uploaded_by`); a name the cited note writes is that person (a Cooptimize attendee by name, else the client's); anything else is noted with the call and is nobody's (PK-1's rule). Without a known writer, "I" is nobody. |
| - | Done | 14. Saving: the paste goes through the upload's own route (`/api/meetings/upload?paste=transcript|notes`, the text as the body, never in the address) and `uploadTranscript`'s checks: the signed-in person (ID-1), only the call's reviewers (an attendee who looks: 403; anyone else: 404), the call's own day; then `savePaste` reads it, refuses what is too long or too short, stores it as the call's transcript and runs the same AI pass. A chat call takes a paste only while it is under its chat's client or Internal (MC-6's rule, checked again at the paste: a call kept under another client before MC-6 is refused, 403 `chat_other_client`). |
| - | Done | 15. Logs say only that a paste was saved (`meeting_paste`), its kind and its line count, or why it was refused (`meeting_paste_refused`: `short`, `long`, `not_text`, `chat_other_client`, with a count): never a word, a name or a title. |
| - | Done | 16. AI off for the client: the paste is saved and shown (Transcript or Your notes), with no pass and no proposals, as a file is. |
| - | Done | 17. Replacing: on a call with a transcript, Use this asks first, naming what is there ("Replace the Teams transcript?", "Replace the pasted notes?", "Replace the Pocket transcript?", then Propose again's words); no changes nothing and keeps the text in the box. A dropped file still asks with its own words. |
| - | Done | 18. Paste in Add a call is held in memory with the new call (as a chosen file is) and sent once the call's page opens; if the server refuses it, the call's page opens its paste box with the text back in it. |

The demo has two calls added by hand: "Northwind export check-in", reviewed from a pasted transcript (a name and a time, the words under it), and "Northwind statements chat", from pasted notes, with fictional words.
