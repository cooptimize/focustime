## DY-1: Day at the time it is (Nov 17)

Unnumbered until merge.

| # | Status | Decision |
|---|---|---|
| - | Done | Computer and tablet only. Day's header row (the day arrows, the date, Today, the day-off mark, Cards or Timeline, Timebox my day, Add and the menu) stays at the top of Day while the page scrolls, in Timeline and Cards; the lines under it scroll away. A block's header stays under it while that block scrolls by, and so do the Timebox bar and the Timeline's to-do column; with the bar up it stays on top and the block headers and the to-do column stick under it. A card's sticky header takes the card's surface, so rows don't show through it. CSS only (`position: sticky` inside Day's own scroller), with Day's header height measured into `--day-head-h`; `scroll-padding-top` keeps a focused element moved by Tab below both. Day's cards clip with `overflow: clip` instead of `hidden`, which drew the same but made each card its own scroller, so a header couldn't stick to Day. |
| - | Done | On today, in the ordinary view, with "Fold blocks that have ended" on, a block whose end has passed folds to one line: the client, the times, done, not done (in the late color once ended), the number of meetings (not free, all-day or unavailable time) and the mark of a call still to review, which opens it. A block with nothing planned says "Nothing planned". The status pill isn't on a folded line (an ended block's risk is moot); its late chip and due dates are kept on it (in Cards they otherwise live in the body the fold hides). Meetings are counted as everywhere else: not personal events or my own timeboxes and solo time. Pure rules in `plan/day-fold.ts`; Day hands each block its answer through `DayFoldCtx` (`ui/dayFold.tsx`); the Timeline's blocks and the cards both read it; Week has no provider, so it never folds. |
| - | Done | The arrow sits at the right end of the block's header, before the card's ⋯, on every block of today in the ordinary view, so a block not yet ended can be folded by hand too. At the left it took the click that opened the block's panel (found by a Week test). Pressing a folded line (anywhere but a control on it) unfolds it; an unfolded header still opens the panel. A real button: "Fold <client>" or "Unfold <client>", `aria-expanded`. |
| - | Done | Never folded by itself: a block with a focus session on one of its to-dos (running or paused), a block whose panel is open, a block the person is in at the moment it would fold (keyboard focus or the pointer in it, or a menu or dialog open, which lives outside the block and may have come from it), which then folds once they leave, any block on another day, anything in Midday check-in, Close out or Timebox my day (while its suggestions are up), and the phone. A drag over a folded block (Cards' to-do drag) opens it until the drag ends. "A to-do in progress" is read as a focus session on it: FocusTime has no other in-progress state for a to-do. |
| - | Done | Whether the person is in a block is read while it is still drawn open: a block that would fold is drawn open first and folds only once Day has looked (before the page is painted, so nothing flickers), so a fold never removes the control under focus. Arrival is measured after that. Opened before any block ended, Day counts as arrived: a block ending later never moves the page. |
| - | Done | A fold or unfold by hand wins over the rule, for today, in this browser (`localStorage` `focustime.dayFolds`: the date and AM, PM or EVE to true or false), forgotten when the date isn't today, never sent to the server. With storage refused it lasts the visit (kept in memory). By hand also wins over the panel and being in it; a focus session on one of its to-dos, the drag, the option off, another day and the flows open it anyway (the arrow isn't offered then), so a running timer is never hidden. |
| - | Done | The option: Day's menu "Fold blocks that have ended", a checkbox item, ticked to start; `[ui] fold_ended` (on by default; an older build skips the key, BH-1) through `ui.set_day_fold`, the person's own like the Timeline switch; also in the command menu. Not in Settings › Display: Day's other view options aren't either. Off, every block is drawn open, folds by hand included, and there are no arrows. The item is never on the phone. |
| - | Done | Arrival: once on each visit to today's Day (per view, Cards or Timeline), after the first block has ended, Day scrolls only if it must, so the block under way (or the next one) shows its header and first lines and the now line is in view: its header goes under Day's header, or, in a long block, the now line to just under halfway (the block's header sticks). Instant, so reduced motion is respected; a fold never animates either. `arrivalScroll` in `plan/day-fold.ts`. |
| - | Done | The block folds live as the clock passes its end (the 30 s app clock), unless the person is in it (above). |

Of either only one boolean is kept, `repeats` on the event; the type and the series id are never kept, logged or sent. No new permission: `type` is a basic property, read with the same token.
