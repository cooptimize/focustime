## ED-2: Rename, move and bulk edit in Backlog's Grid (Nov 14)

Unnumbered until merge.

| # | Status | Decision |
|---|---|---|
| - | Done | ED-2: why. The product owner wants Backlog to be where a backlog gets cleaned up: "the more editing and cleanup and organization we can do here the better." Grooming is mostly four things: fix what it's called, put it under the right parent, set who has it and when, and do that to a handful of rows at once. Before, a wrong title or a story under the wrong feature meant opening each card, each writing on its own. |
| - | Done | Title and parent are fields of Backlog's change set (`plan/ahead-edit.ts` `CHANGE_FIELDS`): staged, shown in Review as before and after, written on Save, undone like the others. Nothing reaches DevOps before Save. They sit in a third table, `ahead_edit_changes` (migration `20261205T0900_ahead_edit_changes`, only adds: `ahead_changes` and `ahead_state_changes` keep their CHECKs, D468); an older build ignores it, so a rollback is safe. Export schema 42. |
| - | Done | The rules are ED-1's, unchanged, applied at stage time and again on the write path: who may (`canEdit`), a title by `cleanTitle` (one line, not empty, 255 at most), a parent only among that client's own items, open, exactly one level up by the process's backlog levels (`moveProblem`; the write path's `moveCheck` is the code `reparent` already had, now shared), never itself, or No parent. Exactly one level up also means a loop can't be made. Area and iteration are left as they are. |
| - | Done | A move stays inside one client by construction: the picker, the drag and the bulk action only ever look among the one client's items (`ahead.stage` and `ahead.stage_bulk` find the parent in that client's read, the write path reads it from that client's project with that client's token and checks its project). An id from anywhere else isn't found. |
| - | Done | FocusTime never changes the order in DevOps. A move writes the parent link only (the old link out, the new one in); no order field is ever in a patch (tests check the ops). There is no drag to reorder: rows light up only as parents, the gaps between rows are never targets, and the words say "Move under". A moved row keeps its rank and its place in the ranked list; its parent label shows the new parent with "Moved, not saved"; opened under a row, it shows under the new parent with the same mark (`plan/ahead-model.ts` lays the staged parent over the item). |
| - | Done | Save writes an item's staged changes in one update: the `fields` patch gains the title as a field and the move as relation ops, behind the one `test /rev`. The DevOps Update page shows fields and relations together in one JSON Patch body with a `test` on `/rev` (its "Add a hyperlink" and "Add an attachment" examples), so nothing needed splitting or ordering. |
| - | Done | Conflicts stay per field, as the change set has them (D658): a new comment or another field changed in DevOps doesn't block a title; the same field changed there is a conflict, named, with Keep mine or Take theirs. This is the one place the Grid differs from the card on purpose: the card's `item_edit` and `reparent` refuse on any newer revision. |
| - | Done | A story card edit while that item has staged changes loses none of them: they are rows in the plan store, reconciled on the next read (the same value landed: the row goes; the same field changed: a conflict; anything else: still ready). |
| - | Done | Undo after Save (`undo_fields`) puts back the old title and the old parent in the same patch, only while DevOps still shows FocusTime's values, as ED-1's undo does. The owner of a renamed or moved item who isn't me gets ED-1's quiet note. |
| - | Done | Rename: F2 on the Item cell, Rename in the row's menu, or an edit button that shows on hover and on focus. The title becomes a box in place; Enter stages, Esc cancels, Tab stages and moves to the row's first editable cell, a click elsewhere cancels (as the other cells' editors do). A refusal shows under the box. Clicking the title still opens the card. |
| - | Done | Move…: M on the Item cell or the row's menu opens ED-1's picker as one of the Grid's popovers (search, the parent now marked, No parent). Drag: the Item cell is the handle, 6 px before it starts; valid rows light, the row under the pointer says "Move under <title>" and so does a label at the pointer; Esc cancels; a drop anywhere else does nothing. The keyboard's equal is Move…, which reaches every parent, shown or not. A refusal says why where it was tried. |
| - | Done | The row's menu (the app's own popup menu; Shift+F10 or the menu key): Rename, Move…, Edit description…, and Undo rename and Undo move while staged. Only on rows I may change. E on any cell of a row opens its story card ready to edit (`openItemCardToEdit`); on a row I may not change the card opens and says why. |
| - | Done | Bulk: Assign to… (one client's own DevOps people, the Grid's picker), State… (only states every ticked row's type takes can be picked; where types differ the others are listed with the rows they fit), Size…, Move to… (only rows at one level of one client; otherwise the button says why when pressed). Each decides per item (`bulkDecide`), stages through the same `stageOne`, and says "Staged N, skipped M" with the reasons. The four older actions are unchanged. |
| - | Done | Review: Title and Parent rows first in an item's group; the item is named as DevOps has it. The list of what the review saved now goes by write log entry id (it compared the server's time with the browser's, so it never showed in the demo), names the fields each write changed, and its Undo and Retry name their item. |
