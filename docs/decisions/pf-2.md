PF-1 found the server sent everything uncompressed (1.5 MB for the first screen where about 410 kB would do) and that a missing script was answered with the page. Both are in how the server sends things. Numbers in `docs/ux/pf2/before.md` and `after.md`. |
| - | Done | STEP 0.3: dev sent the page and a script with no `content-encoding` and no `content-length`, and answered a missing `/assets/` file with the page (200, text/html). Container Apps' ingress passes the app's answer through unchanged; nothing in front compresses. So A was built (the decision "if the hosted files already arrive compressed, skip A" did not apply). |
| - | Done | Documentation read (Nov 16): Container Apps' [ingress overview](https://learn.microsoft.com/azure/container-apps/ingress-overview) and [configure ingress](https://learn.microsoft.com/azure/container-apps/ingress-how-to) (no response compression or setting for it), Node's [zlib](https://nodejs.org/api/zlib.html) (Brotli 0 to 11, gzip 0 to 9, Zstandard experimental; the async functions run on the thread pool). |
| - | Done | The app's files are compressed when the server starts, not by the build: one code path that works the same in the demo, the tests, the developer loop and the image, with no change to the build, the Dockerfile, the dist folder or the service worker's list. `server/static-files.ts` reads every built file into memory once, before the server listens, and makes the compressed forms then; no request reads a file from disk or compresses one. |
| - | Done | Brotli quality 9 and gzip level 9 for files: about 0.2 s for this build at start, within 8% of Brotli 11's size, which took about 3 s (on every replica start and every test server). Zstandard is not offered: Brotli 9 is smaller on these files and every browser that sends zstd sends br. |
| - | Done | Compressed: text files (`.js`, `.css`, `.html`, `.svg`, `.json`, `.webmanifest`) of 1 kB or more, the page and the service worker among them, each form kept only when it saves 10%. Sent as they are: fonts and images (compressed already) and files under 1 kB. |
| - | Done | The form sent is the one with the highest q the browser gives, Brotli on a tie, else the plain file; `Vary: Accept-Encoding` on every answer of a file that has more than one form (the plain one and 304s too); `content-length` on every file answer, HEAD included. |
| - | Done | D: every file but the page has an `ETag`, one per form, from that form's own bytes; `If-None-Match` naming any form's tag (or `*`) is answered 304 with no body and the tag it named. The page stays `no-store` with no tag. The cache lines are unchanged: hashed files immutable, the page no-store, the rest no-cache. |
| - | Done | B: a file under `/assets/` this build doesn't have is 404, `no-store`, empty. Every other unknown address gets the page, as before. PF-1's release handling (one reload, then the line with Retry) works on the 404 (`e2e/pf1.test.ts` now uses the server's real answer). |
| - | Done | B: the service worker's install fetches each shell file and keeps them only when every one came back 200, not redirected, with its own type (a page is never kept under another file's name; a kind of file the worker doesn't name only has to not be a page), all or none. Its matches ignore Vary. |
| - | Done | C: data is compressed only from `COMPRESSED_READS` in `server/compress-data.ts`: `week.load`, `weekplan.load`, `ahead.load`, `roadmap.load`, `status.load`, `inbox.list`, `conversations.list`, `my_promises.list`, `followups.list` and Code's `code.clients`, `code.repos`, `code.folder`, `code.find`, `code.kinds`, `code.search`, `code.inside`, `code.file`. The Guide's and the technical docs' text come with the app's files, not from the server. |
| - | Done | C: the rule is enforced where every JSON answer is written (`writeJson`), from the action an `/api/action` call named: no other route passes one, so a new route or action is plain by default. Also plain: a body under 1 kB, and any answer that sets a cookie. |
| - | Done | C: never compressed, even if listed (`NEVER_COMPRESSED`, a test per kind): `auth.*`, `push.*`, the DevOps write PAT actions, `calendar_link.*`, `settings.*`; and everything under `/auth/`, health, version, the database state, push-to-talk, uploads, chat images and the Teams bot's endpoint (streamed). The reason is the BREACH family of attacks: a secret compressed beside text someone else chooses. |
| - | Done | C: Brotli 4 (else gzip 6) on the thread pool, per answer: about 11 ms for a 1 MB answer (Code's largest file), within 7% of Brotli 5's size at two thirds of the time. Nothing compressed is cached. |
| - | Done | A client's code (`code.*`): compressed for its one answer; what is sent, compressed or plain, is zeroed once written or when the connection closes first; the plain copy is zeroed as soon as it is compressed. JavaScript strings can't be zeroed; they go with garbage collection as before. The Code rules are otherwise unchanged. |
| - | Done | The CSP and every other header are unchanged; JSON answers gain `content-length` (and `vary`, `content-encoding` where they apply). No new dependency, no change to Azure, the deploy workflows or secrets. |
| - | Done | Measuring: `scripts/first-screen-times.ts` gains `--first-visit` (service workers blocked, so every file comes from the server) and `--bytes` (bytes on the wire, files and data apart); `scripts/data-sizes.ts` lists every data read by action. PF-1's runs and first visits came out the same. |
