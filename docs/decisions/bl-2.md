## BL-2: Backlog always in rank order (Nov 14)

Unnumbered until merge.

| # | Status | Decision |
|---|---|---|
| - | Done | The product owner's rule: "in the Backlog view the backlog stack rank needs to always be respected. if viewing the Feature, the features need to be stack ranked by feature and not grouped by epic which is stack ranked." The level picked in Filter › Levels (Epics, Features or Stories, each client's own names from its process) is the list: that client's items at the level, in that level's own backlog order (the order field DV-1 stores per process, ascending; a project with none by target date, said in the client's header). Items at the level above are not rows. One rule (`plan/backlog-list.ts`, `listGroups`), read by the Grid and the Gantt. FocusTime never changes the order in DevOps; nothing here writes. |
| - | Done | STEP 0.4's proof, written first and failing on `main` (`it.fails`): two epics, the first-ranked epic holding the feature ranked third and the second-ranked epic the features ranked first and second. The Grid listed 13, 11, 12 (grouped under its epics); the Gantt by bar start. Both now list 11, 12, 13 with ranks 1, 2, 3. |
| - | Done | Each row shows its rank number: its place among the level's open items in Cooptimize's scope, counted before any filter. Filters and search remove rows and never renumber or reorder what is left (the Epic filter at Features shows ranks 3 and 7 if those are its features). A closed item keeps its place, dimmed, with no rank. |
| - | Done | Each row shows its parent as a label (the type's icon and title) beside its title; a click puts the Epic filter on that parent (the chip says "Feature: <title>" when the parent is a feature, as at Stories). A row with no parent shows none. |
| - | Done | A row opens to what is one level under it, in that level's own order, and those rows open in turn (a caret, Right and Left, Expand all and Collapse all). Rows start closed. Children have no rank number of their own: the number is the rank at the level listed. Epics with Expand all gives the same rows as BL-1's tree for the same data (a test checks it). |
| - | Done | Nothing on the tree is lost: an item under the level with no item at the level above it (a story directly under an epic, a story or feature with no parent) is listed after the ranked rows, the higher level first, each in its own order, with no rank. |
| - | Done | Features is the level when nothing is saved. A level picked is kept in this browser, as BL-1's was. BL-1's "One level as a list" is gone with its checkbox and chip: a saved one, or a link's `fl=`, becomes the level once and is dropped from the saved filters and the address. `l=` wins over `fl=`. `#/backlog/stories` (and the older Backlog mode addresses) open at Stories. |
| - | Done | The Gantt lists the same rows in the same order as the Grid (`tree()` over the list, in its order), each row's accessible name starting "Rank N." at the level listed; the indent is relative to the level listed. Needs attention keeps its own shape (client › epic › feature, as BL-1). |

| - | Done | The demo's Atlas Freight has two epics ranked one way with their features ranked another (`sources/demo/data.ts`), so the demo shows the rule. |

The write preview for Backlog's change set said "Undo in DevOps" on its Save button; it says "Save in DevOps". |
