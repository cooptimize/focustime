P1: migration `20261103T2300_notices_push` adds two user tables: `notices` (the in-app list: what the notifier delivered, once per key, newest 50, read and closed marks; plan-store addNotice, notices, readNotices, closeNotice) and `push_devices` (`push-devices.ts`: one row per browser with push on, the subscription sealed with the data key bound to the person and device id, a coarse label, last sent and failed; never exported).

## host/: the host boundary

Environments (A5): three, one code. **local** is the developer loop (`FOCUSTIME_HOST=local`, `host/local`, the local SQL Server container; retired for daily use, D469). **dev** and **prod** are the hosted app (`FOCUSTIME_HOST=azure`, `host/azure`) in FocusTime-dev and FocusTime, the same image, told apart only by app-level settings from Bicep: `FOCUSTIME_ENV` (About, `/version`, Setup's Start over refused on prod), their own URL, vault, data key, database and logs, and `FOCUSTIME_INVITE_DOMAINS` on prod (D464). ## Running it

Run (developer loop, `system/README.md`): `focustime-open` (starts the service if needed, then opens or focuses the window), or `npm start` (build + server + Chromium app window) when the service is stopped, `npm run dev` (Vite in the server, no HMR; `FOCUSTIME_DB_NAME=focustime_dev` for the dev database), `npm test` (with `npm run db:up` first so the SQL Server half runs; `FOCUSTIME_TEST_SQL=required` makes a missing server a failure), `npm run typecheck`, `npm run db:up` / `db:migrate` / `db:reset` / `db:down` (the local SQL Server container), `focustime export-local` and `focustime import --file <export.json> --user <oid> [--dry-run]`, `npm run screenshot` (needs a running server). `FOCUSTIME_HOST=azure` runs the hosted host (port 8080; secrets from `FOCUSTIME_SECRET_*`, the data key through `FOCUSTIME_KEYVAULT_URL`). Azure: `docs/azure/runbook.md` (deploy, roll back, rotate, logs, delete dev).
