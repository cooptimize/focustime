## store/: the plan store

`store/`: the plan store on one async Conn (sql/conn.ts) with two drivers: sql/sqlserver.ts (mssql: pool, Entra token or SQL login, the retry rule and "waking" status, catalog-typed binds, UTC datetime2) and sql/sqlite.ts (node:sqlite: the demo, the fallback, export-local); sql/tsql.ts (the store's SQL as T-SQL: parameters, MERGE upserts, TOP, brackets), sql/baseline.ts (SQL Server's schema at version 26) and sql/migrate.ts (schema_version, one transaction per migration); open.ts (the store from [database]); plan-store.ts (the store and SQLite's 26 migrations); wake-store.ts (the idle rule's next-due time); import.ts (an export into a store, ids kept, idempotent, dry run) and export-local.ts (plan.db read-only as an export); scope.ts (the one per-person filter, USER_TABLES), isolation.test.ts (two people across every table), claim.ts (rows from before A2 to their owner), accounts.ts (users, sessions, pending sign-ins), user-settings.ts (settings rows and the app keys), user-secrets.ts (sealed secrets, KeyProvider), user-data.ts (export, soft and hard delete) S1 (D458): migrations/ holds the timestamped migrations (named.ts: the name rule, order, shared-prefix check, pending; index.ts the list; 20261103T1700_setup_state.ts the first), run after the numbered ones on both stores and recorded by name in schema_migration_names. setupState, setSetupStep and resetSetup on the store; setup_state is a per-user table (scope.ts). fix/vm-schedule (D465): vm-restores.ts marks next-morning auto-shutdown restores left from before cancelled at server start (all users, once, logged as refused in each person's Azure write log); nothing runs them.

## log/: logging

`log/`: structured logger with a closed set of fields (no headers or bodies); appinsights.ts (A4: the same fields and route names to Application Insights, no bodies)

## fixtures/: sample data

`fixtures/`: sample data (tests, and calendars with no config section); four-day-week.ts (the week shape older tests use); names.test.ts (no real names, addresses or desktop words in the repo)

## e2e/: browser tests

`e2e/`: browser tests (vitest + playwright-core, system Chromium; Playwright's WebKit behind a local TLS front for safari.test.ts): a throwaway demo-mode server per file (harness.ts); real-session.test.ts runs a real (not demo) session on fake live sources and scans every screen for demo data S1: live.ts (liveContext and liveBrowser: a real session on fake sources, shared by real-session and setup), setup.test.ts (the whole first-run flow), pto-about.test.ts (Plan the week's PTO cell and About), shots.ts (shotBoth: a screenshot at 1920 and again at Text size Larger when FOCUSTIME_SHOTS is set).

## .github/workflows/: CI and deploys

`.github/workflows/`: ci.yml (typecheck, tests on SQLite and a SQL Server container, browser tests (WebKit required), Bicep build, image smoke), deploy-dev.yml (on main: CI, image to ACR, migrate, DB user, Bicep what-if and deploy, smoke), deploy-prod.yml (a stub until A5) S1: ci runs on pull requests and pushes to main only, one run per ref (cancel in progress, D455), and saves the tree it tested; deploy-dev's reuse job skips the full suite when the PR's passing run tested the same tree (D456), bakes the build info, and its smoke test checks /version names the commit.

## Dockerfile: the image

`Dockerfile, .dockerignore`: the hosted image: multi-stage, Node 26, non-root, port 8080, FOCUSTIME_HOST=azure, no secrets; S1: ARG BUILD_SHA, BUILD_PR and BUILD_TIME become FOCUSTIME_BUILD_* (D452).

## test/: shared test helpers

`test/`: db.ts (forEachDriver: a store test on SQLite and on SQL Server, skipped with the reason when no server answers, failing under FOCUSTIME_TEST_SQL=required), fill.ts (a person with a row in every table), no-promise-expect.ts, tmp-dir.ts (the run's own temp folder), ports.ts (free ports with a retry when another test takes one first: every server a test starts goes through it), builders/ (aUser, aClient, aWeek, aFocusBlock, aPto, aMeeting, anOutOfOffice, aWorkItem, aWeekConfig: the test data every new or edited test uses)

## Running it

Run (developer loop, `system/README.md`): `focustime-open` (starts the service if needed, then opens or focuses the window), or `npm start` (build + server + Chromium app window) when the service is stopped, `npm run dev` (Vite in the server, no HMR; `FOCUSTIME_DB_NAME=focustime_dev` for the dev database), `npm test` (with `npm run db:up` first so the SQL Server half runs; `FOCUSTIME_TEST_SQL=required` makes a missing server a failure), `npm run typecheck`, `npm run db:up` / `db:migrate` / `db:reset` / `db:down` (the local SQL Server container), `focustime export-local` and `focustime import --file <export.json> --user <oid> [--dry-run]`, `npm run screenshot` (needs a running server). `FOCUSTIME_HOST=azure` runs the hosted host (port 8080; secrets from `FOCUSTIME_SECRET_*`, the data key through `FOCUSTIME_KEYVAULT_URL`). Azure: `docs/azure/runbook.md` (deploy, roll back, rotate, logs, delete dev).
