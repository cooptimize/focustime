## Send feedback (F1)

The feedback module spans four files, with no other dependencies (D509 to D513):
- `plan/feedback.ts`, pure: the window's input (kind, text, where; nothing else), the title, the description and the tags. It has no way to reach the plan, clients or work items.
- `sources/devops/feedback.ts`: the DevOps calls as the app's managed identity (a bearer token for Azure DevOps). It reads the parent, the process's story type, and the default team's iteration; it creates with the parent link in the same JSON Patch (validateOnly for the setup check) and reads back. Logs carry op, status and duration only.
- `actions/feedback-actions.ts`: the service (one per process, with its cached setup check) and the feedback.status, feedback.preview and feedback.send actions. Previews are held 10 minutes; the daily count is in the person's kv. `actions/feedback-types.ts` holds the types the window shares.
- `ui/Feedback.tsx`: the dialog (Write, Preview, Sent or the error), opened from ⋯ and Commands. Settings > Connections shows the setup read only.

`server/main.ts` builds the service from the app settings: preview only and unchecked locally, live or preview only from FOCUSTIME_FEEDBACK_LIVE when hosted. The demo uses `sources/demo/feedback.ts`, a pretend backlog in memory.

## Running it

Run (developer loop, `system/README.md`): `focustime-open` (starts the service if needed, then opens or focuses the window), or `npm start` (build + server + Chromium app window) when the service is stopped, `npm run dev` (Vite in the server, no HMR; `FOCUSTIME_DB_NAME=focustime_dev` for the dev database), `npm test` (with `npm run db:up` first so the SQL Server half runs; `FOCUSTIME_TEST_SQL=required` makes a missing server a failure), `npm run typecheck`, `npm run db:up` / `db:migrate` / `db:reset` / `db:down` (the local SQL Server container), `focustime export-local` and `focustime import --file <export.json> --user <oid> [--dry-run]`, `npm run screenshot` (needs a running server). `FOCUSTIME_HOST=azure` runs the hosted host (port 8080; secrets from `FOCUSTIME_SECRET_*`, the data key through `FOCUSTIME_KEYVAULT_URL`). ## AI-0: the AI provider foundation (Nov 4)

`ai/` is a core module (the host boundary applies): the one way FocusTime asks a model for anything. Settings › AI's Test AI, and AP-2's sorting of asks and Promises, call it.

- `ai/types.ts`: `AiTask` (name, client or "none", instructions), `JsonSchema` (the strict subset), `AiError` with one plain message per kind, `ProviderReply`, `AiLogEntry`, `AiPersonSettings`, `AiStatus`.
- `ai/service.ts`: `createAi(deps)` → `run(task, input, schema)`, `test()`, `status()`. Order: Use AI, Allow AI for the client, a provider with a key, the guard, the person's and the app's monthly caps, one call (one retry on a transient error, Retry-After on 429), the schema check (no retry), then the log row and the app's month total. `aiFor(ctx)` in `actions/dispatch.ts` builds one per person per request from `ActionContext.ai` (the `AiRuntime` from `server/main.ts`), the person's `[ai]` settings, their plan store and the guard's directory (`aiDirectory`: every client but the internal one with its Dataverse and display names, DevOps projects and item ids from `makeDevOps().last()`, nothing fetched), the Cooptimize domains (`inviteDomains`) and their VM.
- `ai/guard.ts`: `guard(text, {client, directory, homeDomains, forbidden})`: the first reason not to send, or null (D496). Pure.
- `ai/schema.ts`: `strictProblems` (the schema strict mode takes), `validate` (paths, never values), `sampleOf` (the stub's answer).
- `ai/openai.ts`: the Responses API adapter: `store: false`, `text.format` json_schema strict, `max_output_tokens`, optional `reasoning.effort`; the answer is the `output_text` parts; usage, refusal, incomplete; 429 rate limit vs quota codes; 408/409/5xx/network transient; timeout by abort. The key goes only into the Authorization header.
- `ai/stub.ts`: no network; answers with the simplest value that fits the schema (or a test's reply), usage at about 4 characters a token.
- `ai/cost.ts`: cost in millionths of a dollar from usage and the app's prices; months (UTC); `fmtUsd`. `ai/view.ts`: Settings › AI's view (safe for the page).
- Store: `ai_requests` (user table: the log, D499) through `PlanStore.addAiRequest`, `aiSpentMicros`, `aiRequests`; `ai_app_spend` (app table: month, cost) through `store/ai-spend.ts` on the database itself. Migration `20261104T1800_ai`.
- Settings: app `[ai]` in `server/appconfig.ts` (provider, model, reasoning_effort, timeout_ms, `[ai.max_output_tokens]`, the three prices, app_cap_usd; `FOCUSTIME_AI_*`); the person's `[ai]` in `config/schema.ts` (use, monthly_cap_usd, allowed_clients) edited by `settingsEdit("ai")` (`allow` adds or removes one client).
